# GLib CodeQL flow review — 2026-11-04

Reviewed the complete `codeFlows` from GitHub's Rust SARIF analysis
`2086851724`, category `/language:rust`, on commit
`96722bbc5ca07302c0ed8702c2d97f2a39f71402`. The seven findings are alerts

## Findings and actual Rust types

| Alert | Reported flow | Why that path is not executable |
|---|---|---|
| 14 | Charset/error out-parameters → generic `from_glib_none` → `ObjectRef` refcount | `console_charset()` returns `Option<GString>`; `charset()` returns `Option<&GStr>`. Their `*const c_char` conversions cannot instantiate the `*const/mut GObject` implementation. Error wrappers return `Error`, never `ObjectRef`. |
| 15 | `GError*` or URI return/hostname → generic `from_glib_full` → `ObjectRef` | File-write failure branches convert an allocated, non-null `GError*` to `Error`. URI success converts its return to `PathBuf` and its nullable hostname to `Option<GString>`. Neither dispatches to `ObjectRef`. |
| 16 | The same charset/error sources → `MyBoxed` conversion generated by a derive | `MyBoxed` is declared inside upstream's `#[cfg(test)]` module in `subclass/boxed.rs`. Its generated pointer conversion has a different concrete type from the string/error wrappers. It is not a production conversion of their output. |
| 17 | Charset/error sources → generic conversion → `Value::copy_into_value` | The concrete generic result types are `GString`, `&GStr` or `Error`, not `Value`. The SARIF path joins distinct trait implementations. |
| 18 | Error/URI sources → generic conversion → `Value::clear_value` | The concrete result types are `Error`, `PathBuf` or `Option<GString>`, not `Value`. The source cannot enter the reported GValue destructor through that generic dispatch. |
| 19 | Pointer-array slot → `drop_in_place<T>` → write a null slot | `T: TransparentPtrType` owns the pointer stored in a slot. Dropping that element frees/releases its pointee, not the GLib allocation containing the array slot. `truncate` decreases length before dropping, clears that still-live slot, and only the collection's destructor frees the array. The analyzer conflates the two allocations. |
| 20 | UUID validator return → generic `from_glib` → `LogLevel` panic formatting | `g_uuid_string_is_valid` returns `gboolean` (`i32`), converted to `bool`. `LogLevel` implements `FromGlib<u32>`. These are different trait instantiations; the UUID text does not flow into this conversion or the numeric panic message. |

The charset/error trace families originate at:

- `auto/functions.rs:344–347`: initialize a `const char*` out-parameter, call
  `g_get_console_charset`, then convert the returned string on its UTF-8 branch.
- `manual_functions.rs:217–220`: `g_get_charset` fills the string out-parameter;
  the nullable conversion produces `Option<&GStr>`.
- `auto/functions.rs:197–208` and `224–237`: initialize a null `GError*` as
  required by GLib, call the file-write API, then convert it **only in the
  non-null error branch**. The C call writes the out-parameter.
- `auto/functions.rs:276–282`: `g_filename_from_uri` returns a path and optional
  hostname in its success branch, or a non-null `GError*` in its error branch.

The out-parameter initialization is required by the C API, not proof that it
remains null after the call. See GLib's official
[charset contract](https://docs.gtk.org/glib/func.get_console_charset.html) and
[error ownership contract](https://docs.gtk.org/glib/func.file_set_contents.html).

## Native regression evidence

`backend/security-tests/glib-variant-iter/src/ffi_contract_tests.rs` exercises:

- Borrowed and owned GObject conversion with exact reference counts.
- GValue clone/drop lifetimes through weak GObject references and boxed Bytes.
- Pointer-array truncation, element destruction and repeated slot reuse.
- Real charset out-parameters with compile-time string result types.
- Real GLib failure out-parameters, cloned errors and nullable URI hostnames.
- Valid and invalid UUID results returning booleans without entering a log-level
  panic.

All five new tests and the three existing VariantStrIter tests pass with release
optimization enabled on macOS ARM64 with native GLib. The probe enables GLib
2.66 APIs solely in its independent test package. No GLib runtime dependency is
added to the macOS/Windows application.

The 121-file upstream integrity verification remains unchanged and passes.
No vendor Rust source, provenance hash, assertion or analyzer exclusion is
changed. Arbitrary null/dangling pointers are never passed to unsafe APIs as a
test of behavior outside their contract.

## Disposition

Classify these seven exact findings as **false positives**, attaching per-alert
flow evidence and this review to GitHub's dismissal record. Keep CodeQL enabled
for the vendor directory so new findings remain visible. A generic null-check
patch would not establish pointer validity and would unnecessarily modify the
verified upstream backport.

Re-review this assessment if the vendor hash, trait result types, collection
ownership code or the analyzer's reported source/sink path changes. Future
findings should be assessed independently.
